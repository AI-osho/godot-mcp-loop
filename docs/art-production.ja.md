# 原画制作からGodotでの確認まで

0.10.0から公開済みで、0.12.0にも同梱しています。任意の原画・素材制作7機能は、0.12.0からのnode_add_treeとは別です。[構成と仕組み](architecture.ja.md) · [導入](getting-started.ja.md)。

流れは「制作方針 → 原画依頼 → 実際の返却PNGの記録 → 再現可能な素材加工 → Godotへの配置 → 通常入力と実画面での確認」です。新しいゲームエンジンや巨大な編集アプリは作らず、既存godot-mcp-loopの編集・実行・検証へつなぎます。作品ごとのゲーム性・物語・コードは制作AIが担当します。

## 前提と、変更しないもの

- `production_plan` と `art_request` はローカルの制作記録を扱い、エディタやPythonが起動していなくても使えます。
- PNGを扱う機能にはPython 3.11以降とPillow 13.0.0が必要です。実機確認はPython 3.13で実施。パッケージ内の `authoring/requirements.txt` を使いますが、ツールが勝手に導入することはありません。実行環境を選ぶ場合の `GODOT_LOOP_PYTHON` はサーバー管理者側の環境変数で、AIからのツール引数ではありません。
- 既存の編集・実行ツールはPillowがなくても使用できます。
- `art_request` 自体は絵を生成しません。既存認証の `openai-codex` / `gpt-image-2-medium`、medium要求を引き継ぐための依頼を準備します。制作AIはクライアントが持つ承認済み画像生成機能を使い、その原本PNGを対象プロジェクト内へ保存してから記録します。
- 画像生成機能を持たないクライアントでは、既存PNGの提供か承認済みの画像生成手段が必要です。生成していない画像やレスポンスを作ったことにはしません。
- 認証情報、画像モデルの全体設定、MCP登録、他profileを変更しません。別providerへの切替、無断high化、新規契約、自動公開も行いません。
- `size` は制作側の要求サイズの記録です。画像生成ツールが同じ名前の引数を受け取る、あるいは指定どおりの実寸を返す保証ではありません。実際の生成手段の対応引数へ渡し、返却PNGの実寸を別に記録します。
- 返却model/qualityは提供元の申告値です。独立したモデル証明、実課金・利用枠・商用権利の確認ではありません。未報告は `null` のままです。

## 追加する7つの入口

| ツール | すること |
|---|---|
| `production_plan` | 作品の狙い、操作、美術方針、場面と素材一覧を新しいJSONへ保存。場面・素材IDや参照関係を検査します。 |
| `art_request` | 計画と素材IDから、場面の文脈・参照画像・修正理由を引き継ぐ原画依頼を保存。状態は `awaiting_external_image` で、生成済みとは表示しません。 |
| `art_register` | 実際のPNGを読み、実寸と保存バイトの指紋、要求と返却品質、採否を記録。任意の `response_file` で生の返却記録も指紋にひも付けます。 |
| `asset_build` | 宣言的な加工レシピから、透過・切出し・足元・縮尺整列・アトラスを作り、新規出力先へPNGと完成台帳を保存。通信や画像モデル呼出しはありません。 |
| `asset_preview` | 加工結果またはアトラスの1フレームを画像として返します。Godot実画面ではないことを明示します。 |
| `asset_verify` | 原画、依頼・返却記録、加工コード、出力バイト、フレーム情報、余分なファイルを読取り専用で検査します。 |
| `asset_scene_add` | 検査済み素材を現在の2Dシーンへ一括配置。足元・位置・縮尺・描画順・フレームを指定し、1回の取り消しで配置グループだけ戻せます。 |

制作記録・原画依頼・返却記録・加工・配置には `dry_run` があります。記録と加工出力は追記型の書出しで、エディタの取り消し対象ではありません。`edit_undo` は原画や台帳を勝手に消さず、シーンに追加したグループを戻します。シーンの保存は別途 `scene_save` で明示します。

## 既存PNGで最初に確認する

対象プロジェクトへ本物のPNGを保存してから、`asset_build` へ次の引数を渡します。これは背景PNGを保存バイトのままコピーする例です。

```json
{
  "output_root": "res://assets/generated/art01",
  "recipe": {
    "version": 1,
    "assets": [
      {"id": "background", "source": "res://art/source/background.png", "key": "none", "fit": "copy"}
    ]
  }
}
```

続けて次を呼びます。

- `asset_verify`：`manifest: "res://assets/generated/art01/manifest.json"`
- `asset_preview`：同じmanifestと `asset_id: "background"`

`output_root` は新しい `res://assets/generated/<英小文字で始まるID>` に限定します。既存の出力先は上書きしません。出力に失敗したことを成功に見せたり、別の画像を代わりに生成したりしません。

## 加工レシピ

各素材には `id`、`source`、`key`、`fit` を指定します。素材名や座標は作品側のデータであり、ツール本体へ固定しません。

- `copy`：`key: "none"`、切出しなし。原本PNGの保存バイトを保ちます。基準点は左上[0,0]。任意の `foot_anchor` は実寸内に限ります。
- `pose`：`frame_size`、`foot_anchor`、`target_height`。最近傍で縮尺を変え、見える足先の帯を指定位置へ揃えます。
- `icon`：`frame_size`、`target_extent`。見える物体の最大辺を基準に中央配置します。足元合わせとは別の処理です。
- `scaled`：`frame_size` と、正の `scale` または `scale_group` のどちらか一方。任意の `foot_y`。同じ機械の状態差分などの大きさを揃えます。
- `scale_groups: [{"id":"machine","target_height":176}]` は、そのグループの最大可視高から1つの縮尺を計算します。各状態を同じ身長へ引き伸ばす処理ではありません。
- `crop` は[left, top, right, bottom]。マゼンタ背景の切出しでは、実際の余白が全周に必要です。空の切出し・原画の欠け・枠外へのはみ出しを拒否します。
- `export: false` のフレームは、中間PNGとして出さずにアトラスの材料にできます。
- `atlases: [{"id":"poses","frames":["idle","loaded"],"fps":6,"loop":false}]` で順序を保って横連結します。各フレームは同寸法・同じ基準点が必要です。半透明を勝手に合成しません。新しいアニメーション原画を生成する機能ではありません。

人物の例です。値は実原画を見て決めてください。この数値をどの画像にもそのまま適用できる、という意味ではありません。

```json
{
  "id": "actor",
  "source": "res://art/source/actor.png",
  "key": "magenta",
  "fit": "pose",
  "frame_size": [128, 176],
  "foot_anchor": [64, 170],
  "target_height": 156,
  "art_record": "res://production/actor-accepted.json"
}
```

既存・自作素材では `art_record` を省略できます。その場合は生成履歴を捏造せず、台帳の未登録原画として明示します。指定した場合は、採用済みの返却記録、PNGの実バイト、依頼、制作計画、参照画像、生の返却記録の対応を確認します。

## Godotで表示して確認する

Node2DまたはControlのシーンを開き、`asset_scene_add` を呼びます。

```json
{
  "manifest": "res://assets/generated/art01/manifest.json",
  "name": "Artwork",
  "placements": [
    {"asset_id": "background", "name": "Background", "position": [0, 0], "z_index": -10, "scale": 1}
  ],
  "dry_run": true
}
```

確認後に `dry_run: false` で実行します。

- `position` は記録した基準点の位置です。人物なら足元、アイコンなら中央、通常のcopyなら左上です。
- `frame` はアトラスの0始まりのフレーム番号。`play: true` は標準アニメーションの自動再生を指定します。
- 単一PNGはSprite2D、アトラスはAnimatedSprite2DとSpriteFramesを使います。
- 名前は勝手に修正せず、重複や不正な名前を拒否します。全配置を事前検査してからグループを追加します。
- 1回の `edit_undo` でそのグループを取り消します。既存のノード・原画・加工ファイルは消しません。

その後は既存ツールを使います。

1. `scene_save` → 意図した本来のシーンから `game_run`。
2. `game_input` で普通のキーやアクションを送り、`game_query` / `game_wait_for` で結果を確認。
3. `screenshot` の実画面を見て、接地、縮尺、前後関係、欠け、日本語UIを確認。`asset_preview` と混同しません。
4. `logs_read` で実行時エラーを確認。作品ごとの経路は既存 `scenario_run` へ記述します。
5. 保存があるゲームなら専用の試験保存先を使い、通常起動・再起動・終了も作品側で検査します。この素材ツールが汎用の保存・進行基盤を自動実装するわけではありません。

診断用の状態設定は通常プレイと分けます。テレポートや直接クリアで、本来の操作経路が通ったことにしません。自動キー入力と本人の試遊も区別します。

## 安全性・制限

- プロジェクト外、保護フォルダ、シンボリックリンク、既存記録・既存buildへの上書きを拒否します。
- 加工出力の確定には、既存ディレクトリを原子的に置き換えないOS機能が必要です（Darwin、Linuxの `renameat2`、Windowsのrename）。非対応環境では上書きへ切り替えず失敗します。reparse属性や物理的なプロジェクト外への到達も拒否しますが、Windows実機の保証ではありません。
- 配置先のシーンと親ノードは、Pythonでの検証待ちに入る前から同一性を確認します。途中で切り替わった別シーンへ無言で配置しません。Godot側のパス探索は、親フォルダごとに4096項目を超える未解決の探索を拒否します。
- 原画・素材・台帳は改変検出用で、署名や悪意ある同一ユーザーに対する安全境界ではありません。既存プロジェクトのコードやimporterも信頼対象です。
- 原画64項目、アトラス16項目、各64フレーム、PNGは32MB/1600万画素、フレーム辺4096、アトラス幅16384などの個別上限と処理総画素数上限があります。JSON要求・台帳も別に制限します。ホスト全体のメモリ・ディスク容量保証ではありません。
- 別OSや別Pillow/zlib環境での保存バイト一致は未保証です。加工コードの変更後は、以前の台帳を合格にせず新しいIDで作り直します。
- Godotが作るPNGの `.import` は、対応する出力PNG名に限って許容します。それ以外の追加ファイルやリンクは検査で拒否します。
- 大きい加工・取込みではMCP待機時間を十分に設定してください（例180秒）。進捗要求がある場合は経過秒を通知し、架空の完了率は出しません。
- 取込み命令をGodotへ送る前の中止は配置を防ぎます。送信後の切断・タイムアウトは「変更されなかった」という証拠ではありません。`scene_tree` を確認してから再試行してください。勝手な再送・削除はしません。
- 面白さ、画風の好み、物語、音の聞き心地は本人の判断です。技術試験だけで合格にしません。

完成したbuildには、台帳とは別の読取り専用 `manifest.sha256` を保存します。台帳の保存バイトを元のチェックサムと
照合するため、レシピと足元情報を同時に書き換えても合格にはなりません。欠落も検査失敗です。台帳の修正後に
チェックサムを作り直して合格させず、新しいIDで再加工してください。同一ユーザーが意図的に台帳・チェックサム・
関連証拠をすべて改変することを防ぐ署名機構ではありません。

PNG処理の開始時にPython 3.11以降・Pillow 13.0.0の一致を検査します。処理コード・依存定義・記録されたPython版や
Pillow版が変わった場合も、以前のbuildを合格にせず新しいIDで再加工します。JSON記録は同じフォルダ内の一時ファイルへ
全量を書き込み・同期してから、既存の名前を置き換えないハードリンクで確定します。非対応のファイルシステムでは
安全側に失敗させ、上書きコピーには切り替えません。書込み途中の失敗で最終名に壊れた記録を残しません。
プロセスの強制終了では未完成の一時ファイルが残る場合があります。停電からの自動復旧基盤を保証するものではありません。
