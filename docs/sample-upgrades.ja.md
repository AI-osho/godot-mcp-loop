# 旧版から何を改善したか

[English](sample-upgrades.md) · [サンプル一覧](samples.ja.md) · [構成と仕組み](architecture.ja.md)

6作品を同じ「目的・操作・再挑戦・観察・試験・プロジェクト」の形式で紹介します。
単純なplatformerは紹介と一覧画像から外し、既存の試験・既定シーン・CLI互換性のために実装を残します。
旧作のルールや素材を作り直す更新ではありません。

## 共通の改善

| 従来 | 今回 | 維持するもの |
|---|---|---|
| 作品の紹介形式と実行手順が不揃い | 6作品の紹介・画像・操作・再挑戦を統一 | 作品固有のルールと素材 |
| リポジトリ内の組込例が中心 | 単体コピーと各作品の操作/設計/変更ガイド | res://examples/...やPlayer等の既存パス |
| 配布版と開発版の説明が混在 | 従来0.11.0の48ツールと現行0.12.0の49ツールを分ける | 公開0.11.0の配布内容 |
| 編集の説明が中心 | 編集→実行→観察→判定と役割・保存の境界を説明 | 通常のGodotプロジェクトとリソース |

公開0.11.0の実際の配布名は[導入の版別表](getting-started.ja.md#配布状態)に示しています。
版表示が同じでも、未公開ソースの機能や作品が公開パッケージに入るわけではありません。
アドオン導入とクライアント登録は別の明示操作で、同じ配布物・実行ファイルを使います。

## 各作品で保つこと・補うこと

| 作品 | 保つこと | 補った説明・検査 |
|---|---|---|
| Falling Blocks | 盤面、回転、出現順、得点 | 移動/回転/落下、再開、固定条件の範囲 |
| Vertical Shooter | 敵とボス、描画、寿命、各入力 | 開始から結果への遷移、256×240比率の録画 |
| Side-scroller | ステージ、ジャンプ、敵/足場、描画 | 操作/再開、通常走行とwarp試験の違い |
| 星剣のルカ | 物語、マップ、会話、戦闘、成長 | 日本語フォント、敗北時の所持金半減、再起動の違い |
| Marble Run | コース、ジャンプ必須区間、接地、残機/復帰 | 操作と結果後の再挑戦、視野/レイ/接触の試験範囲 |
| 灯畑の番人 | 正式化したゲームの1マップ・2塔・3波、独自の絵/効果音 | 単体/組込の画面と座標、通常マウス経路、3つの構築計画 |

## 正本と生成コピー

4作品blocks / shooter / action / rpgと内部platformerはexamples側が正本で、samples側へ単体プロジェクトを生成します。
MarbleとTDはsamples側が正本で、examples側へ組込コピーを生成します。両側を別々に手修正しません。

```sh
node scripts/sync-samples.mjs --check
node scripts/sync-marble-example.mjs --check
```

未知のファイルや外へのリンク、コピーの不一致を検査します。単体ゲームはアドオンを同梱/有効化せず、遊ぶためにAPIキーやPythonを要求しません。
旧作のファイル、入力、素材、リソースパスとルートの既定シーンを保全します。

## TD正式化時の修正

物理ウィンドウだけでなく論理画面も960×640へ揃え、組込時にマウスとUIの座標を保持します。
組込コピーのTexture2Dは古い単体import UIDを残さずパス参照へ変換し、新しいimportでの警告を避けます。
正本の絵やスクリプトUIDは変更しません。

タイトル13・ゲーム30・結果11ノードの計画JSONは実node_add_tree入力です。
ゲームロジック、PNG、短い効果音は別途制作したもので、ノード構築を素材生成の証拠へ置き換えません。

## 検証範囲

紹介6作品には成功予定シナリオ27本があります。内部platformerの成功1本と意図的失敗1本は区別します。
固定乱数・無敵・warp・直接の状態変更は制御用試験です。通常操作で全編を完走した証拠とは扱いません。
画像は実機撮影ですがRPGは序章で、入力・状態・ログ・PCM・人の遊び心地/聴感の承認も別です。
最終配布物は改めて検証し、旧コピーの成功やソースの存在を公開承認へ読み替えません。
